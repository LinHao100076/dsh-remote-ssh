修复：空主机 gate 遮挡创建表单；设置页连接与测试缺少 OTP 输入；设置保存丢失指纹；端口 0 被误当默认值、空跳板被静默删除；下载误匹配根目录和依赖过期映射；慢请求覆盖当前状态；终端退出没有重连入口、多个终端共享同一 tmux；部分上传失败与刷新失败无反馈；取消映射后延迟 cwd 返回重新打开表单。

另修复删除当前主机后未选择剩余主机的状态竞争。Windows / 已安装 Chrome 的自动化运行通过，157 次 fixture API 请求，浏览器未捕获异常为 0；真实剪贴板复制与终端粘贴均断言了结果。HTTP/SSH 的端到端可用性仍需真实 DSH profile 验收。

运行：

```sh
npm ci
npm run build
npx playwright install chromium
npm run test:ui
```

也可通过 `DSH_CHROMIUM_PATH` 指定已有 Chrome/Chromium 可执行文件。GitHub CI 增加独立浏览器任务；`npm test` 保留原有 Node/协议测试。

局限：API fixture 验证按钮发出的请求、字段与界面状态，不替代真实 DSH 的挂载、会话切换和权限策略验收；OTP 模拟服务器提问，真实认证协议由原有 auth/jump 测试覆盖。剪贴板允许权限的路径已测，用户拒绝权限的环境仍可能无法粘贴。未逐个验证所有浏览器、主题、异常 SSH 服务端和并发恶意路径替换场景。

## 文件与同步流程回归（issues #21–#27）

- 测试通过 `apply()` 注册原生侧栏槽位后挂载实际构建客户端，HTTP API 为隔离 fixture；把 `window.prompt` 改为抛错，确认新建目录和同步“下载单个”使用页面内输入，不依赖 Electron 不支持的 prompt。
- 验证目录单击展开、双击进入、面包屑及上传目标；20 MB 浏览器分块上传、失败 abort 与保留原目标；再次选择取消预览、隐藏预览及迟到读取无效；无映射指定完整本地路径下载；从同步页返回立即刷新，以及展开子目录的周期刷新。
- `test/browser-uploads.mjs` 另走真实 HTTP 请求（实际 2 MB 请求体上限）及真实 SSH/SFTP 数据通道，远端使用内存文件系统。20 MB + 17 字节文件 SHA256 一致，最大请求 349638 字节；还覆盖空文件、提前结束、取消、主机/会话隔离、乱序/超大分块、发布 rename 失败及过期清理。
- 尚未用用户实际远端 Ubuntu 执行本分支。下载路径输入代表 DSH 宿主电脑上的路径，没有调用系统原生另存为选择器。文件页每 4 秒刷新带来对应 SFTP 列表请求；不做实时远端文件监听。

## 后续回归（#29、#30）

文件搜索默认请求 `mode: name`，按文件名匹配，结果不伪造内容行号；可显式切换内容搜索，原有大小写、正则及失效请求检查继续覆盖。服务端增加 find 的 NUL 路径记录、名称字面匹配、大小写、引号、内容命中不混入名称结果的测试。终端移除固定快捷键提示，同时验证清屏、剪贴板粘贴仍能执行。
